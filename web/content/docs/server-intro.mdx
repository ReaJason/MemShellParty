以下服务仅我个人遇到的一些场景，与实际攻防场景可能仍有差距，但是在 MemShellParty
中可用于参考进行内存马生成。个别其他服务还请自行辨别其服务类型。如果有其他环境补充，欢迎 PR 交流学习~

## Tomcat

> 官网：https://tomcat.apache.org/

> 版本适配：https://tomcat.apache.org/whichversion.html

> Tomcat 3+ 下载网址：https://archive.apache.org/dist/tomcat

Tomcat 使用的是自己 Catalina 模块提供的 Servlets 实现，限制较少，在 MemShellParty 中，服务类型选 Tomcat 即可生成 Tomcat
内存马。

一般而言，SpringWebMVC 项目大多使用 Tomcat 提供 Servlets 容器功能，比如 Nacos，这种情况下可以选择 Tomcat 内存马注入。其他服务中，致远 OA、Confluence、帆软也是使用 Tomcat。

- Spring Boot 1.x 如果使用默认的 spring-boot-starter-web 1.x 依赖，则使用的 spring-boot-starter-tomcat 1.x 中 Tomcat 版本为 Tomcat 8.x。
- Spring Boot 2.x 如果使用默认的 spring-boot-starter-web 2.x 依赖，则使用的 spring-boot-starter-tomcat 2.x 中 Tomcat 版本为 Tomcat 9.x。
- Spring Boot 3.x 如果使用默认的 spring-boot-starter-web 3.x 依赖，则使用的 spring-boot-starter-tomcat 3.x 中 Tomcat 版本为 Tomcat 10.x。

## Jetty

> 官网：https://jetty.org/

Jetty5 和 Jetty6 版本使用的包名为 `org.mortbay.jetty`，而 7 以上使用的是 `org.eclipse.jetty`，在测试最新的 Jenkins
时，发现 Jetty12 版本支持 ee8 ~ ee11 的环境，包名对应的是 `org.eclipse.jetty.ee8`，这些在 MemShellParty 中均已支持，因此服务类型选 Jetty
即可生成 Jetty 内存马。在 SpringWebMVC 项目中也是有可能使用的。

Jetty 5.x 的 `Request` / `Response` 与 Jetty 6 不同，需要单独选择 `Jetty5` 服务类型（无需设置服务版本），仅支持
Servlet / Filter / Listener 三种挂载类型。

- Spring Boot 1.x/2.x 如果使用的 spring-boot-starter-jetty 1.x/2.x 中 Jetty 版本为 Jetty 9.x。
- Spring Boot 3.0.x/3.1.x 如果使用的 spring-boot-starter-jetty 3.0.x/3.1.x 中 Jetty 版本为 Jetty 11.x。
- Spring Boot 3.2.x+ 如果使用的 spring-boot-starter-jetty 3.2.x 中 Jetty 版本为 Jetty 12.x ee10。

## JBoss

> JBossAS: https://jbossas.jboss.org/downloads

> JBossEAP: https://developers.redhat.com/products/eap/download

JBoss 分为 JBossAS 和 JBossEAP，JBossAS 全版本和 JBossEAP6 使用的 Catalina 模块提供的 Servlets 实现，JBossEAP7/JBossEAP8 的
[Undertow](#undertow) 提供的 Servlets 实现。

因此 JBossAS 4~7 以及 JBossEAP6 服务类型选择 JBoss 进行内存马的生成，而 JBossEAP7/JBossEAP8 需要选择
[Undertow](#undertow) 进行内存马的生成。

JBossWeb 基于 Tomcat，RawWebSocket 与 Tomcat 共用同一份 helper；JBoss 4~7.1、EAP6 的默认 BIO 连接器可直接使用。

## GlassFish

> 官网：https://glassfish.org/

GlassFish 使用的是 Catalina 提供的 Servlets 实现，但是使用了 OSGI 类加载模式，因此类限制较为严重，Apusic V10 和 Primeton V6.5 基于 GlassFish 进行二开，在 MemShellParty 中，服务类型选择
GlassFish 进行内存马的生成。

GlassFish/Payara 的 HTTP 连接器是 Grizzly。RawWebSocket 使用 Grizzly 专属 helper，按连接器版本接管底层
SocketChannel 并自行完成握手与帧协议，不依赖容器的 WebSocket 实现；GlassFish 3 ~ 8、Payara 5 ~ 7
的 Grizzly 1.x/2.x 均可直接使用。

WebSocket 走 Tyrus 的 JSR-356 `ServerContainer`：注入器从 ServletContext 取出容器后注册 Endpoint。
GlassFish 4+ / Payara 5+ 自带 Tyrus，可直接使用；GlassFish 3.x 没有 JSR-356 实现，只能选择 RawWebSocket。

## SpringWebFlux

Spring Boot 项目中基于 reactor 异步 IO 模型的服务组件，底层使用的 Netty，一般常见于各种 SpringCloud 项目，例如网关。服务类型选择
SpringWebFlux 进行内存马生成。

支持 `WebFilter`、`HandlerMethod`、`HandlerFunction` 与 `NettyHandler` 四种挂载类型。`NettyHandler` 直接挂在
Reactor Netty 的 ChannelPipeline 上，不依赖 Spring 的路由；Suo5 仅支持 `WebFilter`。

## Struts2

> 官网：https://struts.apache.org/

Struts2 是基于 XWork 的 MVC 框架，服务类型选择 Struts2 进行内存马生成，挂载类型选择 Action。生成时 URL Pattern
填写 `/<actionName>`，注入器会借助当前 Struts2 请求线程的 `ActionContext`，从 `RuntimeConfiguration` 向
`namespaceActionConfigs` 中每个已有 Action 的 namespace 注册该 Action。根 namespace 访问 `/<actionName>`，
其他 namespace 访问 `<namespace>/<actionName>`。详见 [Struts2 框架内存马](/docs/struts2-shell)。

Action 内存马依赖请求经过 Struts2 的 Dispatcher 过滤器，并需要 classpath 中存在 `struts2-core`
（`com.opensymphony.xwork2.ActionContext`）。底层 Servlet 容器已有对应内存马时，仍优先选择具体容器。

## XXL-JOB

> 官网：https://www.xuxueli.com/xxl-job/

XXL-JOB 是一个分布式任务调度平台，由于 executor 出现过反序列化漏洞，并且弱密码情况下可在 admin 前台下发任务，在 executor 执行任意代码，因此在 MemShellParty 中也提供了 XXL-JOB 内存马的生成，服务类型选择 XXL-JOB 进行内存马生成。
executor 仅支持 Netty Handler 内存马注入。

## Dubbo

> 官网：https://dubbo.apache.org/en/

Dubbo 分为低版本 2.6x Alibaba Dubbo，包名为 `com.alibaba.dubbo.`，后来合并到 Apache 改为了 Apache Dubbo 2.7x 版本和 3.x 版本，包名为 `org.apache.dubbo.`，当前 Dubbo 内存马只针对 Dubbo Provider，对于 Dubbo Consumer 来说直接打对应的内存马即可比如 Spring 框架马。

挂载类型按 Provider 版本选择 `ApacheDubboService`（Apache Dubbo 2.7+/3.x）或 `AlibabaDubboService`（Alibaba
Dubbo 2.6.x），URL Pattern 填写服务接口名；注入器会以该接口名将 shell 导出为 Dubbo Service。
